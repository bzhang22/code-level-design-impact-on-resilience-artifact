# Anonymous Replication Package

## Overview

This artifact supports independent verification and replication of the
experimental results reported in an anonymized ICSE submission on how
source-level implementation choices affect a program's probability of silent
data corruption (SDC) under single-bit hardware faults. It contains the source
implementations studied, the fault-injection configuration and seeds, benchmark
input generators, the raw per-implementation injection results, and scripts that
reproduce the paper's main tables and figures.

All materials are anonymized for double-blind review.

## System Requirements

- **OS:** Linux/macOS/Windows with Docker (the fault injector runs in a Linux
  container). The Python analysis pipeline runs on any OS.
- **Fault injection:** LLFI on LLVM/clang **3.4**, provided via the included
  `Dockerfile` (Ubuntu 14.04 base). Building the image compiles LLVM 3.4 from
  source: **~30–60 min** on a many-core host, **~8 GB RAM**, ~10 GB disk.
- **Analysis pipeline:** **Python 3** (standard library only). `matplotlib`
  optional, for rendering figures (`pip install -r requirements.txt`).
- **build.sh:** any C++ compiler (`g++`/`clang++`).
- **Disk:** the repository is a few MB; the built Docker image is ~10 GB.

## Quick Start

```bash
git clone <repository-link>
cd icse-anonymous-sdc-artifact

# 1. compile-check all programs (needs a C++ compiler; no Docker)
./scripts/build.sh

# 2. regenerate the paper's main tables & figures from the INCLUDED data
#    (Python only, ~seconds — the fastest end-to-end verification)
./scripts/reproduce_main_results.sh

# 3. live fault-injection sanity check (needs the LLFI image; see below)
./scripts/run_quick_check.sh
```

Step 2 needs no Docker and no fault injection: it recomputes the SDC
probabilities, z-statistics, tables, and charts directly from the real
per-implementation counts in `results/raw_summary/`, and prints the regenerated
Table V. It is the quickest way to confirm the paper's numbers follow from the
shipped data.

### Building the fault-injection image (for steps 3+)

```bash
bash docker/downloads/fetch.sh              # download LLVM/clang/LLFI sources (~56 MB)
docker build -t anonymous-sdc-artifact .    # ~30–60 min (builds LLVM 3.4)
docker run --rm -it anonymous-sdc-artifact  # lands in /artifact
# then, inside the container:
./scripts/run_quick_check.sh
```

## Reproducing Main Results

- **All main tables and figures, from included data (no injection):**
  `./scripts/reproduce_main_results.sh` → `results/tables/` and
  `results/figures/`. Regenerates the six-controlled-pair table (Section V) and
  the ten-row Case Studies table (Table V), plus the bar charts.
- **Fresh injection for one experiment (inside the container):**
  ```bash
  ./scripts/run_controlled_pairs.sh --program verdict_encoding --num-injections 5000 \
      --seed 2026 --output-dir results/reproduced/verdict
  ./scripts/run_applications.sh --program running_maximum --num-injections 1000 \
      --seed 2026 --output-dir results/reproduced/rmax
  python3 scripts/aggregate_results.py --input results/reproduced/verdict --output results/processed
  ```

Which command, code, and CSV back each paper result: **`docs/experiment_mapping.md`**.

## Experiment Mapping

Every paper number traces to a raw CSV row and a source directory via
`data/benchmark_metadata/mapping.csv` and `docs/experiment_mapping.md`. The
analysis pipeline (`aggregate_results.py` → `generate_tables.py` →
`generate_figures.py`) performs only arithmetic on the recorded
SDC/Crash/Benign/Hang counts; it does not synthesize any results.

## Fault-Injection Configuration

Single bit flip in the output value of one dynamically executed LLVM IR
instruction; compiled at `-O0`; 1000 injections per program (5000 for Dijkstra);
outcomes classified as Benign / SDC / Crash / Hang against a fault-free golden.
Full details, including the important note that the paper's campaign used LLFI's
default (unseeded) randomisation while the reproduction scripts set a fixed
`fi_random_seed`, are in `docs/fault_injection_protocol.md`.

## Expected Outputs

See `docs/expected_outputs.md` for the files each step produces and the target
numbers (they match the paper). In brief, the six controlled insights are all
individually significant (z from 2.2 to 11.1); across the nine Case Study rows
the mean relative SDC reduction is 38.3%.

## Limitations

- The fault injector is pinned to LLVM/clang 3.4 (an LLFI requirement); it is
  provided as a Docker image rather than a host install. Building that image is
  the one heavy, time-consuming step.
- Reproduced SDC probabilities are statistical estimates: they match the paper
  within the sampling margin (~±3.1 pp at n=1000), not bit-for-bit, because the
  original campaign was unseeded. The base-vs-variant direction is stable.
- Absolute SDC% depends on input size; the `run_*` scripts default to moderate
  inputs for speed. The larger inputs reproducing the paper's exact dynamic
  instruction counts are documented in `docs/experiment_mapping.md`.
- `blackscholes` is floating point; its golden is the one compiler-dependent
  output, and it is the acknowledged scope boundary where the insight washes out.
